# Self-hosted mail server setup

This project is now a webmail client for a real domain mailbox. It does not run
the SMTP receiver, outbound MTA, IMAP daemon, spam filtering, or DKIM signer
inside Flask. Run those services on a VPS with a mail-server stack such as
mailcow Dockerized.

## 1. VPS and network requirements

Use a VPS with:

- Full virtualization.
- At least 6 GiB RAM plus 1 GiB swap for mailcow.
- At least 20 GiB disk before mailbox storage.
- Static public IP.
- Configurable reverse DNS.
- Open inbound and outbound ports: `25`, `465`, `587`, `993`, `80`, `443`.

Do not host the mail server itself on Render free/web services. They are useful
for HTTP apps, but a domain mail server must receive SMTP on port `25` and must
control outbound SMTP reputation from its own IP.

## 2. Install mailcow

Follow the official mailcow installation guide:

<https://docs.mailcow.email/getstarted/install/>

Recommended hostname:

```text
mail.example.com
```

After installation:

1. Create the domain, for example `example.com`.
2. Create one or more mailboxes, for example `admin@example.com`.
3. Generate DKIM keys from the mailcow UI.
4. Confirm SOGo webmail and IMAP login work before using this Flask client.

## 3. DNS records

Replace `example.com` and `203.0.113.10` with your domain and server IP.

```dns
mail.example.com.        A      203.0.113.10
example.com.             MX 10  mail.example.com.
example.com.             TXT    "v=spf1 mx a -all"
_dmarc.example.com.      TXT    "v=DMARC1; p=none; rua=mailto:dmarc@example.com; adkim=s; aspf=s"
_smtp._tls.example.com.  TXT    "v=TLSRPTv1; rua=mailto:tls-reports@example.com"
```

Also set reverse DNS with your VPS provider:

```text
203.0.113.10 -> mail.example.com
```

Publish the DKIM record generated by mailcow. Start DMARC with `p=none`, review
reports, then move to `quarantine` or `reject` when legitimate mail passes SPF
and DKIM consistently.

## 4. MTA-STS

MTA-STS advertises that other mail servers should use TLS when delivering to
your domain.

DNS:

```dns
_mta-sts.example.com. TXT "v=STSv1; id=2026070301"
mta-sts.example.com.  A   203.0.113.10
```

Policy file served over HTTPS at
`https://mta-sts.example.com/.well-known/mta-sts.txt`:

```text
version: STSv1
mode: testing
mx: mail.example.com
max_age: 86400
```

After testing, change `mode: testing` to `mode: enforce` and increase
`max_age`.

## 5. TLS and elliptic-curve key exchange

The Flask app uses Python's default certificate validation, requires at least
TLS 1.2 for IMAP/SMTP submission, and restricts TLS 1.2 ciphers to ECDHE suites
when the local OpenSSL build allows it. TLS 1.3 uses ephemeral key exchange by
default.

For the mail server itself, harden Postfix and Dovecot in mailcow:

- Postfix: <https://docs.mailcow.email/manual-guides/Postfix/u_e-postfix-harden_ciphers/>
- Dovecot: <https://docs.mailcow.email/manual-guides/Dovecot/u_e-dovecot-harden_ciphers/>

The critical policy choices are:

- Submission on `587` must require STARTTLS before authentication.
- IMAP on `993` must use TLS.
- Outbound SMTP should not deliver to remote MX servers that do not offer
  STARTTLS if you require transport encryption for every message.
- Use DANE/TLSA only if your domain has DNSSEC deployed correctly.

## 6. Configure this Flask app

Set environment variables:

```env
MAIL_DOMAIN=example.com
IMAP_HOST=mail.example.com
IMAP_PORT=993
SMTP_HOST=mail.example.com
SMTP_SUBMISSION_PORT=587
FLASK_SECRET_KEY=generate-a-long-random-secret
SESSION_REDIS_URL=redis://redis:6379/0
SESSION_TTL_SECONDS=28800
SESSION_COOKIE_SECURE=true
```

The app stores mailbox credentials only in a server-side session with a TTL. In
production, use Redis over a private network and HTTPS so the browser receives
only a session cookie, not the mailbox password.

## 7. Verification checklist

Run these checks before trusting the server for daily mail:

```bash
openssl s_client -starttls smtp -connect mail.example.com:25 -servername mail.example.com
openssl s_client -starttls smtp -connect mail.example.com:587 -servername mail.example.com
openssl s_client -connect mail.example.com:993 -servername mail.example.com
```

Then verify:

- MX, A, PTR/rDNS, SPF, DKIM, DMARC, MTA-STS, and TLS-RPT are published.
- The server is not an open relay.
- Mail to Gmail and Outlook passes SPF, DKIM, and DMARC.
- Mail from Gmail and Outlook arrives in the IMAP inbox.
- A receiver whose MX does not support STARTTLS is rejected if strict outbound
  TLS policy is enabled.
