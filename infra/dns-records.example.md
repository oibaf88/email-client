# DNS records template

Replace `example.com`, `mail.example.com`, and `203.0.113.10` with your real
domain, mail hostname, and VPS IP.

## Required records

```dns
mail.example.com.        A      203.0.113.10
webmail.example.com.     A      203.0.113.10
mta-sts.example.com.     A      203.0.113.10
example.com.             MX 10  mail.example.com.
example.com.             TXT    "v=spf1 mx a -all"
_dmarc.example.com.      TXT    "v=DMARC1; p=none; rua=mailto:dmarc@example.com; adkim=s; aspf=s"
_smtp._tls.example.com.  TXT    "v=TLSRPTv1; rua=mailto:tls-reports@example.com"
_mta-sts.example.com.    TXT    "v=STSv1; id=2026070401"
```

## Reverse DNS

Set PTR/rDNS at the VPS provider:

```text
203.0.113.10 -> mail.example.com
```

## DKIM

After the first bootstrap, read the DKIM public key generated by
docker-mailserver and publish it as a TXT record.

```bash
docker compose -f compose.prod.yaml exec mailserver setup config dkim
docker compose -f compose.prod.yaml exec mailserver cat /tmp/docker-mailserver/opendkim/keys/example.com/mail.txt
```

## DMARC hardening path

Start with:

```dns
_dmarc.example.com. TXT "v=DMARC1; p=none; rua=mailto:dmarc@example.com; adkim=s; aspf=s"
```

After SPF and DKIM pass consistently, move to:

```dns
_dmarc.example.com. TXT "v=DMARC1; p=quarantine; rua=mailto:dmarc@example.com; adkim=s; aspf=s"
```

Then, when you are confident legitimate mail is aligned:

```dns
_dmarc.example.com. TXT "v=DMARC1; p=reject; rua=mailto:dmarc@example.com; adkim=s; aspf=s"
```
